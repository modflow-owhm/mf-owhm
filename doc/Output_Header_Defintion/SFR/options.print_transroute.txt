
SFR package OPTIONS block PRINT_TRANSROUTE output file

Writes for each time step every SFR reach's kinematic-wave routing information
(TRANSROUTE with IRTFLG > 0): the routing time step, the flows that are routed,
the flood wave celerity and Courant number, the storage weight (TRANSROUTE_WEIGHT),
the change in channel storage, and the water created or lost by the routing solution.
Values are from the last routing time step (NUMTIM) of the time step.

The option may also be used without routing (IRTFLG = 0 or no TRANSROUTE)
to get the CELERITY and COURANT numbers of the steady streamflow.
A COURANT number well above 1 means that a flood wave crosses the reach within
one time step, so routing has little effect; a COURANT number well below 1 means
that routing may change the results.

Reaches that are not routed (routing not active, or a steady state stress period) set:
   FLOW_IN_PREV, FLOW_OUT_PREV, and WEIGHT to NaN, 
   STORAGE_CHANGE and ROUTING_ERROR to zero, and
   COURANT to NaN in steady state stress periods (the time step length has no meaning).

The kinematic-wave routing solves for each reach and routing time step the outflow from
   FLOW_IN - FLOW_OUT + lateral inflow - seepage = STORAGE_CHANGE
where 
   STORAGE_CHANGE = LENGTH * ( WEIGHT*(A(FLOW_OUT) - A(FLOW_OUT_PREV)) + (1-WEIGHT)*(A(FLOW_IN) - A(FLOW_IN_PREV)) ) / DELT_ROUTE
and A(Q) is the channel flow area at streamflow Q. FLOW_IN and FLOW_OUT in this balance are
time weighted with their previous values by the WEIGHT input that follows IRTFLG and NUMTIM 
(a different weight than TRANSROUTE_WEIGHT).
See TRANSROUTE_WEIGHT in doc/Option_Block_Cheatsheets/SFR_Options_Cheatsheet.sfr for a description of WEIGHT and AUTO.

The output may be text or binary format.

If the output file is text format, then it will contain a single header line
followed by the output written for each time step. If the output file is binary format,
then each time step writes a binary record for each reach containing only the output data.


/-------------------------------------\
|                                     |
|    Text File Header Definition      |
|                                     |
\-------------------------------------/

DATE_START                 is the starting calendar date of the time step in the form: yyyy-mm-ddThh:mm:ss
                              (NaN if the DIS package does not specify a STARTDATE)
PER                        is the stress period number
STP                        is the time step number
DELT              [T]      is the time step length
SIMTIME           [T]      is the simulated time at the end of the time step
SEG                        is the stream segment number
RCH                        is the reach number within the segment
DELT_ROUTE        [T]      is the routing time step length, DELT/NUMTIM (DELT when the reach is not routed)
LENGTH            [L]      is the reach length
FLOW_IN_PREV      [L3/T]   is the reach inflow  at the end of the previous routing time step (NaN when not routed)
FLOW_OUT_PREV     [L3/T]   is the reach outflow at the end of the previous routing time step (NaN when not routed)
FLOW_IN           [L3/T]   is the reach inflow  at the end of the routing time step
FLOW_OUT          [L3/T]   is the reach outflow at the end of the routing time step
CELERITY          [L/T]    is the flood wave speed, dQ/dA (change in streamflow over change in flow area),
                              at the smallest of FLOW_IN_PREV, FLOW_OUT_PREV, and FLOW_IN,
                              or at the smaller of FLOW_IN and FLOW_OUT when not routed.
                              It is zero when the flow area does not change with flow (ICALC 0).
COURANT                    is CELERITY * DELT_ROUTE / LENGTH, the fraction of the reach the flood wave crosses in one routing time step
                              (NaN in steady state stress periods)
WEIGHT                     is the storage weight used (TRANSROUTE_WEIGHT); with AUTO it is max(0.5, 1 - COURANT).
                              When a reach has no flow and AUTO is used, it is 1.0 (NaN when not routed)
STORAGE_CHANGE    [L3/T]   is the rate of change of the water stored in the channel; positive when storage increases (zero when not routed)
ROUTING_ERROR     [L3/T]   is the water created (positive) or lost (negative) by the routing solution.
                              It is not zero where a negative outflow was reset to zero, which mostly
                              happens with a WEIGHT less than max(0.5, 1 - COURANT) (zero when not routed)


/-------------------------------------\
|                                     |

\-------------------------------------/


DATE_START          CHARACTER(19), starting date formatted as 'yyyy-mm-ddThh:mm:ss'
PER                 INTEGER

DELT                DOUBLE
SIMTIME             DOUBLE
SEG                 INTEGER

DELT_ROUTE          DOUBLE
LENGTH              DOUBLE
FLOW_IN_PREV        DOUBLE
FLOW_OUT_PREV       DOUBLE
FLOW_IN             DOUBLE
FLOW_OUT            DOUBLE
CELERITY            DOUBLE
COURANT             DOUBLE
WEIGHT              DOUBLE
STORAGE_CHANGE      DOUBLE
ROUTING_ERROR       DOUBLE


/----------------------------\
|                            |
|   Additional Information   |
|                            |
\----------------------------/


Date output is formatted using ISO 8601-1:2019 standard without a time zone designation:
https://en.wikipedia.org/wiki/ISO_8601#Combined_date_and_time_representations

The general format is:
yyyy-mm-ddThh:mm:ss
                   where:
                         yyyy is the four digit Gregorian year
                         mm   before the T is the two digit month number       (01 to 12)
                         dd   is the two digit day of the month                (01 to {28, 29, 30, 31}, depending on the month)
                         T    calendar date and 24-hour clock time separator
                         hh   is the hour within the day                       (00 to 23 hour)
                         mm   after the T is the two digit minutes in the hour (00 to 59 minute)
                         ss   is the two digit seconds of the minute           (00 to 59 second)

Output is in model units that uses an
   L as a place holder for Length, L2 is for area, L3 is for volume and
   T as a place holder for Time

which are defined in the DIS package as being:
   L: Feet, Meters, Centimeters, and Undefined
   T: Seconds, Minutes, Hours, Days, Years, and Undefined

------------------------------------------------------------------------------------------

The MODFLOW-OWHM standard binary formatting is set to
Fortran Unformatted Stream (C style binary).

The description of each header indicates the Fortran variable
that is used to write the binary recorded.

The following explain their storage use:

Keyword       Storage      Default Fortran Type  Python Numpy Type       Fortran 2003 Standard
DOUBLE        8 bytes      Double Precision      numpy.dtype('float64')  REAL(kind=real64)
INTEGER       4 bytes      Integer               numpy.dtype('int32')    INTEGER(kind=int32)
CHARACTER(X)  X × 1 bytes  Character(X)          numpy.dtype('SX')       CHARACTER(len=X)
SNGL          4 bytes      Real                  numpy.dtype('float32')  REAL(kind=real32)
